## 2. Label convention

Raw `label` = 0 means **phishing** (inverted vs. the usual convention; confirmed on the dataset page). Everything downstream uses `label = 1` for phishing.

Empirical check: 7.92% of phishing-labelled URLs contain a classic phishing marker (credential-lure keyword, raw IP host, `@`) versus 0.09% of legitimate-labelled URLs (**89x** higher) — polarity check **passed**.

## 5. Shortcut audit

How differently do the classes behave on trivial URL-shape indicators, and how good is the one-line rule "indicator present => phishing"?

| `has_query` | Query string present | 6.04% | 0.00% | 59.88% | **CLASS-EXCLUSIVE** |
| `has_at_symbol` | '@' anywhere in the URL | 1.50% | 0.00% | 57.94% |  |
| `ip_host` | Host is a raw IP address | 0.60% | 0.00% | 57.55% |  |
| `not_bare_https_homepage` | Anything other than 'https://host[/]' (http, path, query or fragment) | 71.83% | 0.00% | 87.97% | **CLASS-EXCLUSIVE** |

Majority-class baseline accuracy: **57.30%**. The single rule `not_bare_https_homepage` alone reaches **87.97%**.

> **WARNING — shortcut learning risk.** Class-exclusive indicators: `uses_http`, `has_path`, `has_query`, `not_bare_https_homepage`. Each is (almost) never present in one class while common in the other. The legitimate class appears to be built from a different population than the phishing class, so a model can score highly by recognising *how the URLs were sourced* rather than *what phishing looks like*. Headline accuracy on this data must not be trusted on its own.

## 6. Consequences for modelling

- Feature engineering (M1.2) must be able to produce a **host-only view** of a URL (scheme, path, query removed) so models can be trained and compared without the sourcing artefacts above.
- Model comparison (M1.4) must include a **path/scheme ablation** and report both views side by side.
- Because legitimate URLs with paths are absent, generalisation to real user URLs cannot be measured on this data alone; an **external validation set** containing legitimate URLs with paths is needed before any claim about real-world performance.
